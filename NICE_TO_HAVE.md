# Nice to have

- **agentik-r1, an untested respawn.** A launcher's successor might start after a tool packet deletes its repo's own `marketplace.json` but before the switch. What does it load from a folder-source marketplace whose file is gone? The cache should serve it, but nobody has tried. Test it once in a scratch `CLAUDE_CONFIG_DIR`, or install no tool packet's merge before the switch.
- **agentik-r1, the mv/ln race.** Between `mv` and `ln -s` in a folder move, a writer could recreate the old folder and split state. The cold window removes the writers. A move helper that refuses while `lsof +D` shows the folder open would remove the race itself.
- **agentik-r1-commons, bounded's suite.** `scripts/bounded` came over byte-identical, but its tests stayed in agentik-session's `tests/test_bounded.py`. Bringing that file here would test the canonical copy where it lives; the packet's reads did not name it.
- **agentik-r1-commons, the marketplace's versions.** Each entry's version is the one on its repo's main on 2026-10-13, and `marketplace-check` checks only that it is semver. A local target that compares each entry with its checkout's `plugin/.claude-plugin/plugin.json` (no network) would show the drift after a release. Landed in packet version-check (2026-10-16): `scripts/marketplace-versions` and `make versions`, which `make check` runs when every checkout is present.
- **agentik-r1-commons N1, sync's self-check.** `scripts/sync` refuses commons only by its resolved path, so a second clone of commons can be the target and be overwritten; a marker such as `bin/agentik` in the target could refuse it too.
- **agentik-r1-commons N2, local-marketplace's inputs.** `make local-marketplace` splits an `AGENTIK_CODE` holding a space, passes an `AGENTIK_CODE` that does not exist, and exits 2 under `make -f <path>` run from another folder.
- **agentik-r1-commons N3, the semver digits.** `marketplace-check`'s `\d` also accepts non-ASCII digits; `[0-9]` or `re.ASCII` would hold versions to ASCII.
- **agentik-r1-commons N4, a ruling, not a defect.** `renamed` treats `NICE_TO_HAVE.md` and `CHANGELOG*` as records at any depth, and `design/`, `bugs/` and `history/` only at the repo's root.
- **agentik-r1-commons N5, the front door's edge names.** A tool named `help` is listed but cannot be dispatched, since `agentik help` is the list; and `agentik help nosuch` exits 3, as not installed.
- **rf1 (2026-10-14), the vendored copies, S3.** The research fixes changed the canonical `scripts/hygiene` (the `renamed` old ids end at a word boundary, rf1-3) and `scripts/bounded` (its docstring states the load rule, rf1-1). The five tool repos and the organization profile still vendor the earlier bytes; `scripts/sync <repo>` in each, at that repo's next packet, brings them over and rewrites `scripts/vendored.sha256`.
- **A plugin changed under an old version (2026-10-14), S3.** A check, vendored into every plugin repo's `make check`, that fails when `plugin/` changed after the commit that last changed `plugin.json`'s version. Claude Code refreshes an installed plugin only on a new version, so such a change never reaches an install. Today's repro: `claude plugin update session@agentik` printed that session was already at the latest version, 2.0.0-alpha.14, while the installed copy's hooks (`run`, `session.ts`, `session.test.ts`) and `skills/session/SKILL.md` differed from the checkout; respeak's installed 0.8.0 differed from its checkout in six files (`agents/respeak.md`, `config/include.md.tmpl`, `config/respeak.config.yaml`, `corpus/lexicon.yaml` among them). Both were bumped by hand, to 2.0.0-alpha.15 and 0.8.1, and GUIDE §7 now states the rule. A second face, 2026-10-16: the marketplace's own `version` lines can trail the plugins' (session read alpha.15 while its plugin.json was alpha.18); installs read plugin.json, so nothing broke, and the observer bumped it by hand. The same check could compare each marketplace line with its plugin.json on the remote's main. Landed in packet version-check (2026-10-16): the canonical `scripts/plugin-version-check`, vendored by `scripts/sync` as a fourth copy, and the local compare, `make versions`. Left: each plugin repo's next sync packet copies it in and adds it to that repo's `make check`; the compare against the remote's main needs the network and is not built.
- **version-check (2026-10-16), the optional index lock.** `scripts/plugin-version-check` runs `git status`, which may refresh the index and take `index.lock`; beside another git command in the same checkout that can fail the check with exit 2. Running its git calls under `GIT_OPTIONAL_LOCKS=0` would make it read only.
